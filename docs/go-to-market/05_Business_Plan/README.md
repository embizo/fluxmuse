# FluxMuse business plan

| File | What it is |
|---|---|
| `FluxMuse_Business_Plan.docx` | The full business plan (~40 pages): 16 sections plus appendices A–F |
| `Business_Plan_Summary.md` | Two-page executive summary in Markdown, for email or a data room |
| `README.md` | This file |

Audience: angels, VCs, banks and development-finance institutions (SEFA, IDC, NEF, TIA and similar),
supporting a **R46M seed raise** (≈US$2.49M; founder decision 2026-10-05, sized to the v3 model).

Every figure traces to `../06_Financial_Model/model_summary.json` (Financial Model v3, Base case), the
model's Python mirror (`derived_tables.json`), `../00_FACTS_AND_ASSUMPTIONS.md` or
`../08_Prospects/CURRENT_OFFER.md`. Nothing is typed by hand (the summary is generated by
`build_summary.py`), and the QA script fails the build if a figure cannot be traced.

**What changed in v2.0 (October 2026):** rebuilt on model v3 and the current offer. Nine plans in three
bands; partner wholesale R6,999; no trials and no pilot (a first group set up by hand instead); payments
live in South Africa only, with pawaPay and Fincra pending; the R46M ask; and an honest financial section:
the seed reaches profitability in the Base and Upside cases only, the Conservative case fails and the
headroom is thin. Appendix C is now "First group and case-study template".

## 1. Placeholders to fill

Every `[[PLACEHOLDER]]` is **bold on yellow** in Word. Use Find for `[[` to walk them. There are 131
placeholder runs. The important groups:

**Company and legal (section 2)** — registration number, founding date, registered and operating
address, directors, cap table, B-BBEE level, tax and VAT numbers, auditor, banker, trade mark status,

first-group pace, pay-at-sign-up and Free upgrade rates, Founding Member end date and uplift, FX
assumptions, referral commission, and every `[[CONFIRM]]` in the text.

**Operational** — settlement terms, security policy and penetration test, hosting regions, target
dates for switching on checkout and Meta publishing, and the VAT plan.

## 3. House rules this document follows

- **No customers, no pilot, no results, ratings or testimonials.** The honest angle is a small first
  group of businesses set up by hand. Case-study targets are labelled "Target (goal)".
- **Status labels from CURRENT_OFFER §3:** live (newly launched), being switched on, not available.
  Facebook and Instagram publishing and FluxMuse checkout are never described as live.
- **Payments:** live in South Africa only; pawaPay and Fincra are contracted, accounts pending.
- **The Conservative shortfall and the thin headroom are stated**, next to every profitability claim.
- **Market figures are labelled "est." with a source** and must be re-verified before external use.
- **Partner economics are labelled illustrative.** The R6,999 partner price is a permanent wholesale
  price, never a launch discount.
- **CURRENT_OFFER §5 never-write list** is enforced by `qa_business_plan.py`.

## 4. Rebuilding after the model changes

The financial model is the source of truth. If it changes, rebuild in this order:

```bash
cd <repo root>
V=<venv>/bin/python                      # python-docx + Pillow + openpyxl

# 1. Rebuild the model itself (regenerates model_summary.json and all chart PNGs)
$V docs/go-to-market/_build/financial_model.py

# 2. Re-derive the detail tables (headcount by department, COGS, cash flow, hiring plan)
$V docs/go-to-market/_build/business_plan/derive_model_tables.py

# 3. Rebuild the document and the summary
$V docs/go-to-market/_build/business_plan/build_business_plan.py
$V docs/go-to-market/_build/business_plan/build_summary.py

# 4. QA: structure, TOC, images, tables, placeholders, forbidden claims, number trace
$V docs/go-to-market/_build/business_plan/qa_business_plan.py
```

Step 2 prints `mismatches vs model_summary.json: []`. If that list is ever non-empty, the mirror and
the published JSON disagree — stop and fix the model before rebuilding the document.

Step 4 exits non-zero on failure. Its **number trace** extracts every R, ₦, KSh, GH₵, $ and %
figure in the document and checks it against the model, the derived tables and the facts file; any
figure it cannot justify is listed and fails the build.

Optional preview (no Word or LibreOffice needed; approximate page count, launches and closes its own
headless Chrome):

```bash
$V docs/go-to-market/_build/business_plan/preview_proposals.py html /tmp/bp-preview
CDP_UDD=/tmp/chrome-profile node docs/go-to-market/_build/business_plan/preview_proposals.mjs /tmp/bp-preview
$V docs/go-to-market/_build/business_plan/preview_proposals.py png /tmp/bp-preview
```
